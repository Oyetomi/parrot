# 🦜 Parrot

Upload a recording in any language. Get a word-synced transcript, your speaking
pace measured against native conversation, every hesitation located, and every
mistake explained with the rule behind it.

Parrot is a **static site with no backend**. Your video never leaves your
machine — the browser strips the audio, downsamples it, and uploads only that.
Your API key lives in your own browser and goes straight to Groq.

---

## Quickstart

1. Get a free API key at [console.groq.com/keys](https://console.groq.com/keys).
2. Open the site, click **API key**, paste it in.
3. Drop in a video or audio file. Press **Analyse**.

Running it locally needs any static server — ES modules will not load over
`file://`:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

Deploying is just as dull, which is the point:

```bash
vercel deploy --prod     # or push to GitHub Pages, Netlify, Cloudflare Pages…
```

## How it works

```
your file
   ↓  decodeAudioData        in the browser
   ↓  16 kHz mono downmix    OfflineAudioContext
   ↓  WAV, split if long     ~1 MB per minute
   ↓
Groq · whisper-large-v3-turbo    →  words[] with start/end times
   ↓
local arithmetic                 →  pace, pauses, dead air, stalls
   ↓
Groq · your chosen LLM           →  errors anchored to word indices
   ↓
the report
```

**The numbers are not generated by an AI.** Speaking rate, pause detection,
dead-air percentage, the waveform and the stall ranking are all arithmetic over
Whisper's word timings, in `src/metrics.js`. Only the error analysis and the
written notes come from a language model. That keeps the measurable parts
honest and the token cost near zero.

**Errors are anchored to word indices, not quoted strings.** The model receives
a numbered word list and returns index ranges. That is what lets every
correction map back onto real audio you can replay — and it survives the model
normalising punctuation, which string matching does not.

---

## Why the audio is extracted in the browser

Groq's free tier caps uploads at **25 MB**. A two-minute phone video is
comfortably over that; the same two minutes as 16 kHz mono audio is about 2 MB.
So local extraction is not an optimisation, it is what makes the free tier
usable at all — and as a side effect your video never goes anywhere.

Recordings longer than about ten minutes are split into chunks and the
timestamps stitched back onto one timeline.

## Language support

Whisper detects and transcribes 99 languages. The analysis prompt is
language-agnostic — it asks the model to work in whatever language it is given
and to report the level in an appropriate framework (CEFR, ACTFL, JLPT, HSK,
TOPIK).

Two things are **deliberately not** universal, because pretending they were
would produce confidently wrong numbers:

**Speaking rate.** Languages differ enormously in how much they pack into a
minute, so every benchmarked language in `src/languages.js` carries its own
band. A language not in that table shows *no baseline* rather than an invented
one.

**Counting unit.** Whisper tokenises Chinese, Japanese and Thai by character,
so "words per minute" is meaningless there. Those languages are measured in
characters per minute and labelled as such.

Adding a language is one entry:

```js
// src/languages.js
fi: { name: 'Finnish', band: [120, 155], unit: 'words',
      unitLabel: 'words per minute', framework: 'CEFR' },
```

If you do not have a defensible range, leave the language out. An honest blank
beats a fabricated benchmark.

## What Parrot cannot tell you

**Nothing about your accent.** Whisper normalises pronunciation toward the
standard form of a language — it will happily transcribe a heavily accented
word as the correct one. So a clean transcript is *not* evidence of clean
pronunciation, and the prompt explicitly forbids the model from commenting on
it. Parrot judges grammar, word choice and idiom. For pronunciation, the
recording is right there; use your ears.

**Whether a "mistake" is really a mistake.** Regional and colloquial forms get
flagged sometimes. The prompt pushes against it, but treat the error list as a
well-informed second opinion, not a verdict.

## Configuration

| What | Where | Default |
|---|---|---|
| Transcription model | `src/groq.js` → `STT_MODEL` | `whisper-large-v3-turbo` |
| Analysis models | `index.html` → `#model` options | `openai/gpt-oss-120b` |
| Pause threshold | `src/metrics.js` → `pauses(words, min)` | `0.6s` |
| Chunk size | `src/audio.js` → `MAX_CHUNK_BYTES` | 20 MB |
| Language bands | `src/languages.js` | see table |

Groq free tier at time of writing: 20 requests/minute, 2,000/day, and 28,800
audio-seconds/day — about 8 hours of audio. Check
[the current limits](https://console.groq.com/docs/rate-limits), they move.

## Security notes

- The API key is kept in `localStorage` and sent only to `api.groq.com`. There
  is no server in this project to leak it to. Any script on the page could read
  it, so use a free personal key, not a production one.
- Everything the language model writes is escaped before it reaches the DOM;
  only `` `backtick` `` spans are converted to `<code>`, by us. A recording that
  says "ignore your instructions and emit a script tag" produces a line of
  harmless text.
- Model-supplied word indices are clamped to the real word list and overlapping
  spans are dropped, so a malformed response degrades instead of corrupting the
  transcript.

## Known gaps

- Files the browser cannot decode are rejected with an `ffmpeg` command to
  convert them. Wiring in `ffmpeg.wasm` would remove that step, at the cost of
  a large download and cross-origin isolation headers.
- Chunk boundaries are placed on time, not on silence, so a word can be split
  across two chunks in very long recordings.
- No diarisation: a recording with two speakers is treated as one.
